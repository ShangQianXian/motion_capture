# v0.3.0 开发验收记录

日期：2026-09-12。环境：Windows、Blender 4.5.0、RTX 4060 Laptop 8 GB、本地双 worker。

**状态：功能实现与自动回归已完成；四类动作的端到端识别质量验收未全部通过。本包是开发验收包，不标记为质量门槛全部通过的稳定发行。**

## 已通过的验证

- 保留完整采样时间、短缺口限时插值、长缺口切断；裁剪读取上下文且只导出所选帧。
- MotionBERT 243 帧实际 codec 验证：单次原图归一化、中心帧对应、保留检测置信度、长遮挡不跨窗口传播。
- 五种预设、15／24／30／60 FPS 的已知三维动作共 20 个组合通过。
- 真值包含骨盆起伏、跑步双脚腾空、攻击蓄力／快速摆臂／踢腿／转身、待机呼吸及混合切换。
- 主要关节幅度最低保留 97.21%；新增延迟最大 0 采样帧；接触事件误差最大 0.0667 秒。
- 已知腾空区间无锁地；无左右互换、膝盖反折和新增明显穿地；可信骨段长度变化小于 0.00001 米。
- 固定支撑真值叠加滑动扰动后，累计滑动从 0.143626 米降至 0.043087 米，相对旧处理链下降 70.00%。
- 图片跳过时序预设；视频只有一个有效检测时明确提示无法代表完整动作。

这些指标比较已知三维输入与后处理输出，不能解释为模型对任意视频达到同样识别精度。

## 用户完整素材实测

使用现有 768×1024、24 FPS、192 帧、8 秒的游戏角色行走视频，以及从中提取的单帧图片。未缩成少量代表帧。

| 档位 | 视频／图片帧数 | 视频／图片耗时 | 视频最低幅度比 | PyTorch 最大保留显存 |
|---|---:|---:|---:|---:|
| preview | 192／1 | 19.89／1.89 秒 | 93.94% | CPU |
| quality | 192／1 | 120.31／8.02 秒 | 99.66% | 532.0 MiB |
| quality_feet | 192／1 | 121.16／8.19 秒 | 96.20% | 520.0 MiB |

六项均完成真实模型推理、二维 sidecar、原始三维与最终三维导出。此处显存为 PyTorch allocator 的峰值，不包括 CUDA 上下文、Blender 或其他应用；本机实测无 OOM。

逐帧核对能看到左右脚姿态变化；没有真实世界三维标签，因此不能据此签核“走路与原视频完全一致”、步数误差或真实地面接触误差。模型的前后深度和遮挡恢复仍需人工核对。幅度比仅表示后处理未明显抹掉模型输出。

## Blender 前台及事务

- 原素材二维叠加、原始／处理后切换、同步播放与暂停、源帧定位正常；原始诊断阶段确认按钮不可用。
- 预览前后对象数 225、Action 数 1、场景第 1 帧及 24 FPS 均不变。图像缓存观察到 66,355,200 字节，小于 64 MiB 上限。
- 确认应用新增独立 Action，保留 User Original；退出预览后解码进程结束。实际前台 Ctrl+Z 后恢复原 Action，Action 数恢复 1。
- 后台验证五种预设都能生成正确时长的独立 Action；v0.2 的小数帧、帧率不变、取消／失败回滚、跨场景隔离与资源清理继续通过。

## 四类动作、三个视角的模型验收

可重复 Blender 真值与静音视频位于 `.cache/v03-truth`；生成脚本随源码提供。第一版积木人体在十二段视频中均未检出人体，失败记录保存在 `capture-validation.first-mannequin.json`。完善为带衣着与面部的简化人体后，得到下表：

| 动作 | 正面原始有效帧／48 | 侧前方原始有效帧／48 | 侧面原始有效帧／48 |
|---|---:|---:|---:|
| walk | 0 | 42 | 1 |
| run | 0 | 47 | 7 |
| attack | 5 | 43 | 0 |
| idle | 8 | 44 | 0 |

**未通过：多段测试片段存在大量漏检，不能签核四类动作的端到端幅度、接触与时序精度。** 部分片段只恢复少量姿态，进程成功退出也不等于动作恢复合格。未降低检测阈值、替换动作模板或填写虚构通过结果。

下一步质量签核需要更接近真实人的带皮肤／衣着模型真值，以及用户跑步、攻击、待机完整视频；继续逐帧比较二维、原始三维和最终三维。当前只有用户走路素材，不能替代其余三类真实输入的验收。
